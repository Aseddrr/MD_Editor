# LightMark 布局与滚动边界修复设计

日期：2026-08-10
目标版本：0.1.2

## 背景与问题

当前界面在文件树或 Markdown 内容较长、较宽时会突破窗口的可视区域，表现为：

- 左侧文件目录不能在自身区域内上下滚动。
- 顶部工具栏和底部状态栏被内容挤出窗口。
- 编辑区或预览区看不到上、下边界，滚动条超出窗口。
- 左侧标题同时显示“文件”和文件夹名称，占用空间且不符合用户期望。

根因是若干 Grid/Flex 容器没有形成完整的高度约束链，文件树也没有被指定为可收缩的滚动子项。超宽表格、代码块等内容还可能扩大 Grid 的最小内容尺寸。

## 方案比较

### 方案一：仅给文件树增加滚动属性

修改最少，但只能处理左侧目录，不能保证工具栏、状态栏和预览滚动条始终处于窗口内，不采用。

### 方案二：锁定窗口布局并明确滚动责任（采用）

从应用根节点到工作区建立完整的 `min-width/min-height/overflow` 约束；文件树、大纲、编辑器和预览分别成为自己的滚动区域；对超宽 Markdown 元素增加边界保护。改动集中在现有 HTML、CSS 和少量元素绑定中，不改变应用架构。

### 方案三：重构 DOM，为每个区域增加新的滚动包装层

边界最明确，但会扩大标记结构、事件绑定和回归范围。现有四个内容节点已经足以承担滚动职责，因此不采用。

## 已批准设计

### 窗口结构

- 应用根节点固定占满 WebView 可用宽高，并隐藏根级溢出。
- 顶部工具栏保持 47 像素固定行，底部状态栏保持 27 像素固定行。
- 中间主体只能使用剩余空间，不能依据子内容扩大窗口布局。
- 侧栏、工作区和编辑/预览面板均允许收缩，并裁切越过自身边界的子内容。

### 左侧导航

- 将“文件”标题改为“目录”。
- 删除文件夹名称和“正在扫描”等副标题；扫描状态仍通过现有内容和错误提示反馈。
- 左侧从上到下排列为文档大纲、水平分隔条、目录筛选与文件列表。
- 大纲默认占可分配高度的 60%，目录占其余空间；两部分均保留防止内容被完全压没的最小高度。
- 分隔条支持鼠标拖动，键盘方向键可微调，双击恢复默认比例。
- 调整后的大纲比例写入现有本地偏好设置，并在下次启动时恢复；窗口缩小时对恢复值重新限制，避免任一区域越界。
- 保留目录刷新按钮和文件名筛选框。
- 文件目录占满其分区的剩余高度并独立纵向滚动。
- 文档大纲占满其分区的剩余高度并独立纵向滚动。

### 编辑与预览

- 编辑器只在编辑面板内部滚动。
- 预览只在预览面板内部滚动。
- 长段落和链接允许在可用宽度内换行。
- 代码块和表格的超宽内容在预览区域内部横向滚动，不能扩大外层 Grid。
- 图片、SVG、视频和画布不得超过预览区宽度。
- 分栏、仅编辑和仅预览三种模式使用同一套边界规则。

### 错误与兼容边界

- 不修改文件读取、保存、自动保存、最近文件、文件关联和窗口关闭逻辑。
- 不改变 Markdown 解析或清理规则。
- 空目录、空大纲和扫描失败继续使用现有提示方式。
- 无效或旧版本的侧栏比例设置回退到默认 60%，不阻止应用启动。
- Windows 最小窗口尺寸仍为 860×560；修复同时验证默认 1280×800 尺寸。

## 验证方案

### 自动检查

- TypeScript 类型检查和 Vite 生产构建通过。
- 现有前端测试全部通过。
- Rust 格式检查、静态检查和测试全部通过。
- 增加布局契约测试，验证关键滚动节点和根级高度约束仍存在。

### 实际界面压力验证

使用包含大量标题、长段落、超长代码行、宽表格、深层列表和宽图片的 Markdown 文档，并使用包含大量文件的目录验证：

- 默认尺寸和最小尺寸下，顶部工具栏与底部状态栏始终可见。
- 文件目录、大纲、编辑器和预览各自在边界内滚动。
- 大纲默认占比高于目录；将分隔条拖到上下边界时，两部分仍可见且可独立滚动。
- 鼠标拖动、键盘微调、双击复位和重启恢复比例均有效。
- 所有滚动条都停留在对应可视区域内。
- 分栏、仅编辑、仅预览以及浅色、深色主题均无布局溢出。
- 目录点击、大纲跳转、打开文件和保存文件功能没有回归。
