# LightMark 文档切换滚动归零修复设计

日期：2026-08-10
目标版本：0.1.4

## 目标

修复打开另一份 Markdown 文档或从目录切换文档后，编辑区、预览区或大纲偶尔从文档底部开始显示的问题。切换成功后应稳定显示文档顶部，同时不改变重复点击当前文档时保留当前位置的现有行为。

## 根因

- 文档内容替换后，编辑器沿用上一份文档的光标位置；聚焦时 WebView 会自动滚动到该光标。
- 预览区和大纲是持续存在的滚动容器，替换子内容不会保证其滚动位置回到顶部。
- 当旧光标或滚动偏移超过新文档长度时，浏览器会将位置限制到新文档底部，因此问题只在部分切换组合中出现。

## 方案比较

### 切换文档时统一归零（采用）

在另一份文档成功读取并渲染后，将编辑器光标、编辑区、预览区和大纲的位置归零；立即执行一次，并在下一动画帧再次校正。改动集中，直接消除旧文档状态泄漏。

### 只重置滚动位置

改动最少，但编辑器随后聚焦旧光标时仍可能重新滚到底部，不能稳定解决问题。

### 记忆每份文档的阅读位置

可以恢复上次阅读位置，但需要新增持久化、失效清理和多视图状态规则，超出本次故障修复范围。

## 已批准设计

- 成功切换到不同路径的文档后，编辑器光标置于第 0 个字符。
- 编辑区、预览区和大纲的横向与纵向滚动位置都归零。
- 先立即归零，再在下一动画帧复核，覆盖 DOM 重排和聚焦造成的二次滚动。
- 编辑器使用阻止页面滚动的聚焦方式，状态栏同步显示第 1 行、第 1 列。
- 新建文档采用相同归零规则。
- 重复打开当前路径只聚焦编辑器，继续保留用户当前位置。
- 文件目录自身的滚动位置保持不变。
- 文件选择取消、读取失败或离开当前文档被取消时不改变任何滚动位置。

## 验证

- 单元测试覆盖光标归零、立即滚动归零和下一帧二次归零。
- 全量运行前端测试、TypeScript 构建、Rust 格式检查、静态检查和测试。
- 原生窗口回归验证长文档之间通过目录切换时，编辑区、预览区和大纲均从顶部显示。
- 验证重复点击当前文档仍保留当前位置，窗口关闭和文件关联打开不回归。
- 验证通过后构建 0.1.4 安装包并更新 `D:\LightMark`。
