# Windows 关闭与文件双击打开修复设计

## 问题

1. 当前关闭监听器无条件调用 `preventDefault()`，然后在同一个关闭链中再次调用 `close()`，导致窗口无法可靠退出并残留进程。
2. 应用既没有读取 Windows 启动参数中的 Markdown 文件路径，也没有在安装包中声明 `.md` / `.markdown` 文件关联，因此作为默认应用启动后只显示空窗口。
3. 应用已运行时再次双击文件会创建新的进程，缺少把路径转发到现有窗口的机制。

## 修复方案

- 未修改文档收到关闭请求时不拦截，让系统直接关闭。
- 有未保存内容时同步调用 `preventDefault()`：已有路径文档先保存，未命名文档询问是否放弃；确认退出后调用 `destroy()`，避免再次触发关闭事件。
- Rust 端从启动参数中挑选第一个真实存在的 `.md` / `.markdown` 文件并返回规范化路径；前端完成窗口事件注册后读取并打开该路径。
- 加入 Tauri single-instance 插件且优先注册。第二个实例启动时验证参数中的 Markdown 路径，把路径发送给主窗口，并恢复、显示和聚焦主窗口。
- 在 `bundle.fileAssociations` 中声明 `.md` 与 `.markdown`，让 NSIS 安装后把 LightMark 注册为可选编辑器。
- 增加 `NSIS_HOOK_PREUNINSTALL`：卸载前检测安装目录中的 `lightmark.exe` 是否被占用。如果文件仍被锁定，提示用户先关闭应用并中止本次卸载，禁止先移除卸载器和注册信息后留下主程序。
- 版本从 `0.1.0` 升级到 `0.1.1`。

## 安装替换

- 先完成源码测试、release 构建及行为验收。
- `D:\LightMark` 当前只有旧 EXE、没有系统卸载项；旧卸载器已删除自身但因进程占用留下主程序。因此精确终止旧 LightMark 进程后删除该目录，再使用新版 NSIS 静默安装到同一路径。
- 不修改用户的 Markdown 文档目录。
- Windows 是否把 LightMark 设为默认程序仍由用户选择；安装包只负责注册支持的文件类型。

## 验收

- 空白窗口收到标准关闭请求后，进程自行退出，不需要任务管理器。
- 使用含空格与中文的 Markdown 路径冷启动，主窗口标题显示文件名。
- 主实例已运行时再次用 Markdown 路径启动，第二个实例退出，主窗口聚焦并显示该文件名。
- 新版卸载器在 LightMark 运行时拒绝卸载且保留自身；应用退出后能够完整移除程序文件与卸载项。
- 前端测试、Rust 测试、类型检查、Rustfmt、`cargo check --locked`、Tauri release 与 NSIS 构建通过。
- 新版安装到 `D:\LightMark` 后存在 `0.1.1` 卸载项，安装后的 EXE 重复通过关闭与文件参数检查。
